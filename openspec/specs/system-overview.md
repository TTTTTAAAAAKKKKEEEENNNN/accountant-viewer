# 会计三表沙盘 · System Overview

> **代码工程位置**：前端工程位于本仓库的 [`/web`](../../web) 目录下（`accountant-viewer/web`）。

---

## 1. 产品定位

一个 **会计三表联动教学 / 演示沙盘**。

- 用户通过录入"业务事件"（如购料、赊销、分红、结转）
- 系统按复式记账规则自动生成分录
- 实时演示 **资产负债表(BS) / 利润表(PL) / 现金流量表(CF)** 三张报表的联动变化与勾稽关系
- 重点教学场景：**净利润 → 本年利润 → 利润分配—未分配利润** 的结转链路

面向对象：会计初学者 / 教学场景 / 财务知识可视化演示。

## 4. 核心数据模型

```typescript
// 数据流:
//   业务事件 Event  --template.build()-->  会计分录 JournalEntry
//                                                |
//                                                v
//                                        科目余额 AccountBalance (派生, computed)
//                                                |
//                                                +--> BS 表
//                                                +--> PL 表
//                                                +--> CF 表 (直接法, 依赖分录上的 cfCategory 标签)

interface Account {
  code: string;              // 唯一主键
  name: string;
  type: 'ASSET'|'LIABILITY'|'EQUITY'|'REVENUE'|'EXPENSE';
  direction: 'DEBIT'|'CREDIT';
  parentCode: string | null; // 树形结构
  isLeaf: boolean;           // 只有叶子科目才能记账
  statement: 'BS'|'PL'|'BOTH';
  isContra?: boolean;        // ⭐ 是否为备抵科目（如累计折旧、坏账准备、累计摊销、各类减值准备）
                             //    语义：名义上属于某一类（如 ASSET），但其正向余额应从所属类别中扣减；
                             //    报表汇总时按 -1 处理。与 direction 正交：direction 管记账借贷方向，
                             //    isContra 管报表汇总正负号，两者都要保留。
}

// 期间只以"月"为真源；季度是派生视图（见 §4.1）
interface Period {
  id: string;              // 如 "2025P01"（月度期间的唯一 id）
  name: string;            // 如 "2025年1月"
  kind: 'MONTH';           // 目前只有月度期间；预留字段方便未来扩展
  year: number;            // 2025
  monthNo: number;         // 1..12
  quarterNo: 1 | 2 | 3 | 4;// 派生分组用
  startDate: string;       // 如 "2025-01-01"
  endDate: string;         // 如 "2025-01-31"
  order: number;           // 全局序号，用于排序
  status: 'OPEN' | 'CLOSED';
}

interface JournalLine {
  accountCode: string;
  debit: number;
  credit: number;
  cfCategory?: 'OPERATING'|'INVESTING'|'FINANCING'|'NONE';  // 打在货币资金侧，用于直接法 CF
  memo?: string;
}

interface JournalEntry { id; eventId; periodId; date; summary; lines: JournalLine[]; isClosing?: boolean }

interface BusinessEvent { id; periodId; templateCode; params; description; createdAt; entryIds: string[] }

interface EventTemplate {
  code; name; category: '经营'|'投资'|'筹资'|'结转';
  params: EventParamDef[];
  build: (params, ctx) => Omit<JournalEntry,'id'|'eventId'|'periodId'>[];  // 纯函数生成分录
}

interface AccountBalance {
  accountCode; periodId;
  openingDebit; openingCredit;
  periodDebit; periodCredit;
  closingDebit; closingCredit;
  closingBalance;    // 按科目方向的正向余额
}
```

**核心计算流**：业务事件 → 会计分录 → 科目余额 → 三表；余额和三表全部是派生数据（Pinia getter），只保存事件+分录这一份真源。

## 4.1 期间模型（月度 P + 季度 Q 视图）

> 用户决策：**期间以月为最小单位（P1~P12），季度（Q1~Q4）是 3 个月的汇总视图**。

### 4.1.1 命名与真源

- **P = Period（月度）**：格式 `{YYYY}P{MM}`，如 `2025P01`、`2025P12`
- **Q = Quarter（季度）**：格式 `{YYYY}Q{n}`，如 `2025Q1`，**不落库、不能录入事件**，仅在展示层聚合 3 个月
- 用户录入事件、结账、分录归属，**只能在 P 上**；Q 只出现在期间矩阵表头和报表列头

### 4.1.2 结转频率

| 结转类型 | 频率 | 触发时点 |
|---|---|---|
| 结转损益 → 本年利润 | **每月** | 每个 P 末（作为该 P 的一个结转事件） |
| 本年利润 → 未分配利润 | **每年一次** | **P12 末** |

每月 PL 表因此都是"当月发生额"的干净视图；`本年利润` 科目余额在每年 P1~P11 累积，P12 末清零结转到 `利润分配—未分配利润`。

### 4.1.3 Q 汇总的语义（⚠️ 时点 vs 流量要分开）

季度视图不落库，展示时按下述规则计算：

| 报表类型 | 数据性质 | Q 汇总规则 |
|---|---|---|
| **BS 表**（资产/负债/权益） | 时点数 | 取 Q 内**最后一个 P** 的月末余额；**绝不相加** |
| **PL 表**（收入/费用/利润） | 流量数 | Q 内 3 个 P 的发生额**直接求和** |
| **CF 表 · 各分类净流入** | 流量数 | Q 内 3 个 P 的净流入**直接求和** |
| **CF 表 · 期初现金** | 时点数 | 取 Q 内**第一个 P** 的期初现金 |
| **CF 表 · 期末现金** | 时点数 | 取 Q 内**最后一个 P** 的期末现金 |

实现放在 `engine/quarterView.ts`，是一层纯展示适配器，不改动底层 P 级数据。

### 4.1.4 默认期间与当前期间

- **默认生成**：`2025P01 ~ 2026P03`（共 15 个 P，覆盖完整年度 + 跨年分红演示）
- **默认选中期间**：打开应用时 = **当前系统月份**（若不在已生成的期间内，则回退到最近的 `OPEN` 期间）
- 用户可自由切换到既往月、未来月；未来月默认 `OPEN`，可随时录入
- 期间的**新增/删除**在 M7 里程碑做 UI；目前从配置文件初始化

### 4.1.5 期间矩阵表头示意

```
         │  2025Q1（合并）    │  2025Q2（合并）    │ ... │ 2026Q1（合并）
         │ P01 │ P02 │ P03 │ P04 │ P05 │ P06 │ ... │ P01 │ P02 │ P03
─────────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┼─────┼─────
库存现金 │  ... 单元格：该月末余额 ...
```

折叠 Q1 后：`Q1 汇总列` 一列合并显示 `2025P03 末`（BS）或 `P01+P02+P03`（PL/CF）；用户点击 Q 表头展开 3 个 P 列。

## 6. 可配置的报表结构（简化版）

> 用户决策：**先不做计算公式**——报表只是"把科目按分组摆出来"，分组可展开折叠，逐级向上求和即可。表达式、正负号、跨行引用等高阶能力**留到后续里程碑再扩展**。

### 6.1 结构 = 分组树

一张报表是一棵**分组节点树**，每个叶子节点绑定一个（或若干个同性质的）明细科目。层级示例：

```
资产负债表 (BS)
├─ 资产
│  ├─ 流动资产
│  │  ├─ 库存现金       (绑定 1001)
│  │  ├─ 银行存款       (绑定 1002)
│  │  ├─ 应收账款       (绑定 1122)
│  │  └─ ...
│  └─ 非流动资产
│     ├─ 固定资产       (绑定 1601)
│     ├─ 累计折旧       (绑定 1602)   ← 简化版原样展示，不做净值扣减
│     └─ 无形资产       (绑定 1701)
├─ 负债
│  ├─ 流动负债 ...
│  └─ 非流动负债 ...
└─ 所有者权益
   └─ ...
```

利润表、现金流量表结构同理：只是一棵**收入/费用**或**经营/投资/筹资**的分组树。

### 6.2 类型定义

```typescript
interface ReportNode {
  key: string;              // 唯一 key
  label: string;            // 显示名，如 "流动资产"
  accountCodes?: string[];  // 叶子节点绑定的明细科目 code 列表；分组节点为空
  children?: ReportNode[];  // 子节点；叶子节点为空
  defaultExpanded?: boolean;
}

interface ReportConfig {
  key: 'BS' | 'PL' | 'CF';
  name: string;
  root: ReportNode[];       // 顶层节点数组
}
```

**没有** `formula`、`expr`、`sign`、`group` 等字段——统统删掉。

### 6.3 求值规则（逐级汇总）

计算某期间某节点的金额：

1. **叶子节点**：把 `accountCodes` 里所有科目在该期间的"按科目方向的期末正向余额"相加，**备抵科目（`isContra: true`）按 `-1` 参与求和**：

   ```
   leafAmount = Σ ( account.isContra ? -balance : +balance )
   ```

   示例：某报表节点"非流动资产"绑定 `1601 固定资产`（30 万）和 `1602 累计折旧`（isContra=true，5 万），叶子求和 = 30 - 5 = **25 万**（净值）。
2. **父节点**：所有子节点金额之和（子节点已带符号，父节点直接累加即可）。
3. **UI 展示**：树形表格（如 `a-table` 的树形模式），父节点默认展示汇总数、可展开看明细；每个期间一列。备抵科目行 label 建议前缀"减："（如"减：累计折旧"），做视觉提示。

> ✅ 求和逻辑复用 `engine/balanceCalculator.ts` 里科目树"父科目递归求和"能力——只不过这里换成"按报表分组"再求和一次。
> ⚠️ **注意**：`isContra` **仅影响报表汇总**（`reportAggregator`），**不影响期间矩阵/科目树的原始余额展示**（`balanceCalculator` 的父科目求和不做符号翻转）——期间矩阵定位是"试算平衡表"，累计折旧就应原样显示正数余额。

### 6.4 与科目树的关系

- **科目树**（第 5 节）负责"记账 / 勾稽 / 借贷方向"，是**会计的骨架**。
- **报表树**（本节）负责"给人看"，是**展示的骨架**，可以完全按科目树 1:1 摆放，也可以自由分组。
- 两者**解耦**：改动一边不影响另一边；报表节点只通过 `accountCodes` 单向引用科目。

配置文件：`web/src/data/reportTree.config.ts`。

## 7. 事件模板库（17 个）

用户在 UI 上选择模板 + 填参数，系统自动生成分录。每个模板保证 `Σdebit === Σcredit`。

| 分类 | 模板 |
|---|---|
| **经营** | 现购原材料、赊购原材料、赊销商品、现销商品、收回货款、支付工资、**计提应付职工薪酬**、**支付应付职工薪酬**、计提折旧 |
| **投资** | 取得投资收益、购买固定资产 |
| **筹资** | 股东投入资本、取得短期借款、宣告分红、支付股利 |
| **结转** | 期末结转损益 → 本年利润、年末结转本年利润 → 未分配利润 |

**关键设计**：现金流分类（`cfCategory`）打在"货币资金侧"的分录行上，直接法 CF 表遍历分录即可归集。结转类分录 `isClosing=true`，不计入现金流。

配置文件：`web/src/data/eventTemplates.ts`。

## 8. 现金流量表（直接法）

> 用户决策：**先用直接法**

原理：遍历所有分录，找到涉及"货币资金"科目（`1001` 库存现金 / `1002` 银行存款）的行，按对方分录行上打的 `cfCategory` 归集：

- 借货币资金 → `inflow` 累加到对应分类
- 贷货币资金 → `outflow` 累加到对应分类
- 结转分录跳过

期初/期末现金 = 库存现金 + 银行存款 的期初/期末余额之和。

实现：`web/src/engine/cashFlowCalculator.ts`。

## 10. Pinia Store 划分

| Store | 职责 | 持久化 |
|---|---|---|
| `accounts` | 科目表（可配置） | ✅ `av.accounts` |
| `periods` | 期间 + 当前期间 | ✅ `av.periods` |
| `events` | 业务事件 + 会计分录（**真源数据**） | ✅ `av.events` |
| `balances` | 余额 + 三表（**派生数据**，全部走 getter） | ❌ |

Store 之间存在跨引用（events↔balances），全部在 action/getter 内部调用 `useXxxStore()`，避免模块顶层求值，运行时安全。

## 12. 边界与校验（用户误操作防护）

在 `engine/validators.ts` 和 `stores/events.ts` 中已经拦截：

| 场景 | 处理 |
|---|---|
| 借贷不平衡（容差 0.005 元） | ✋ 拒绝录入，提示借方合计 / 贷方合计 |
| 分录少于 2 行 | ✋ 拒绝 |
| 单行借贷同时>0 或同时=0 | ✋ 拒绝 |
| 金额为负 / NaN / Infinity | ✋ 拒绝 |
| 引用了不存在的科目 | ✋ 拒绝 |
| 使用非叶子科目记账 | ✋ 拒绝，提示"请使用明细科目" |
| 期间已结账时录入 | ✋ 拒绝 |
| 期间已结账时删除事件 | ✋ 拒绝，提示"请先反结账" |
| 事件参数必填 / min / number 类型 | ✋ 拒绝 |
| 结转分录不计入现金流 | ✅ `isClosing=true` 跳过 |
| 结转时无余额可结（空事件） | ✋ 拒绝，提示"无需生成分录" |
| 科目下还有子科目时删除 | ✋ 拒绝 |

## 13. 测试覆盖

`web/src/__tests__/engine.spec.ts` 6 个核心断言（"生命线测试"）：

1. 每条分录借贷必须平衡
2. **资产 = 负债 + 所有者权益**（演示数据每期都成立）
3. 拒绝借贷不平衡的事件
4. 拒绝对已结账期间录入
5. 结转后"本年利润"余额应为 0
6. 金额非法参数应被拒绝（负数、字符串、缺失）
